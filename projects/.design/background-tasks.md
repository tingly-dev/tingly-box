# 后台任务：项目线程里也看得见

> 后台任务 = Claude Code 用 `run_in_background` 启动的命令，或后台子 agent（reviewer、长时间测试）。它们活得比启动它们的回合长。
> 相关：`message-channel.md`（汇报扣下，`background.go`）、`live-updates.md`（事件流、`thread` 事件）。

## 问题

文件夹会话（Workdir）里后台任务一直是完整的：顶栏"N 个运行中"按钮、任务面板（命令 + 实时输出 / 子 agent 的步骤与回复）、详情栏的"后台任务"卡片、侧栏会话行的任务提示。**项目里的工作线程和协调者看不到**。沿数据链路逐段看：

| 环节 | 现状 | 断在哪里 |
|---|---|---|
| Claude Code 流（`task_started` / `task_notification` / `background_tasks_changed`） | 所有会话相同 | 无 |
| agentboot `engine`：转成 `task` 条目，`live` 里记每个会话正在运行的任务集 | 所有会话相同 | 无，但 `trackTasks` 在条目**追加之后**才更新 `live`，追加时读到的是上一个集合；进程退出（空闲回收、一次性进程）只清 `live`，**不留事件**，页面上任务永远"运行中" |
| Projects 存储 | 所有线程都存 `task` 条目；项目线程另存"X: completed"系统行 | 无 |
| `GET /threads/:id` | 返回 `background_tasks`（实时集合） | 无；但 `Thread` 本身（列表、`thread` 事件、协调者上下文）**没有任务数**，只有这个接口有 |
| `syncBackground` | 文件夹会话：改状态并发 `thread` 事件。项目线程：只提前放出扣下的汇报 | **项目线程任务集变化时不发 `thread` 事件**，卡片、看板无从刷新 |
| 前端 | 全部以"文件夹会话"为条件 | `ThreadPanel` 里 `tasks` 只在 `session` 时计算；详情栏卡片 `folder &&`；顶栏按钮和菜单项 `session &&`；`ProjectPage` 从不取实时任务 |

各界面今天是否能看到：

| 界面 | 文件夹会话 | 项目线程 | 协调者 |
|---|---|---|---|
| Overview 卡片 / 看板 / 顶部带 | 状态点是"工作中"，无任务数 | 同左：只有"工作中"和上一轮的汇报，不知道是在等后台任务 | — |
| 线程详情栏 / 协调者 Status 页 | 有"后台任务"卡片 | **没有** | Status 页只数各状态线程数 |
| 对话（transcript） | 调用上有 `background · running` 标签、子 agent 卡片、结束时的任务卡 | 调用上的标签有；结束有一行系统消息；顶栏无入口 | 协调者提示词里线程表只有 `status=working` |
| 侧栏 | 会话行有任务提示 | 无 | — |

根因一句话：**任务数据只挂在 `GET /threads/:id` 和文件夹页的专用状态上，没有进入 `Thread` 这个所有界面共用的对象，前端又把展示限定在文件夹会话。**

## 决定

1. **`Thread.running_tasks`（只读、不入库）。** 值来自 `engine.BackgroundTasks`，在线程被送出去的每个地方填上（`Threads.Annotate` / `publish`）：列表、项目详情、线程详情、`thread` 事件、协调者提示词和 `list_threads` / `get_thread`。进程没了集合就空，所以不存：存下来的数在重启后一定是错的。
2. **任务集变化时一定发 `thread` 事件**（项目线程和文件夹会话一样），卡片与看板据此刷新。engine 里 `trackTasks` 挪到追加之前，保证读到的集合就是事件描述的那个；进程终止时补发一条空的 `background_tasks_changed`，页面不再卡在"运行中"。
3. **一处定义，各处同一个说法。**
   - 卡片（Overview 列表 / 看板 / 顶部带 / 对话里的线程卡）：小标 `N 个任务`；工作中的线程副标题改为"N 个后台任务运行中"，不再重复上一轮的汇报（它不是新消息）。需要用户的线程（waiting / failed）仍显示等待原因。
   - 打开的线程：顶栏按钮"N 个运行中"（窄屏）或详情栏"后台任务"卡片（宽屏）。项目线程没有任务时不出这张卡（文件夹会话始终有，因为那里是它的固定位置）。顶栏的小标不重复显示。
   - 协调者 Status 页：线程卡里加一行"后台任务：N 个运行中，分布在 M 个线程"，没有任务就不出现。
   - 协调者提示词：线程表里 `background_tasks=N`，并解释它是线程显示 working 的原因、汇报会在任务结束后到，**不要去催**。
4. **不增加聊天消息。** 任务进度只改状态和数字，不进对话流（与 `message-channel.md` 的分级一致）：开始 = 调用上的 `background · running` 标签；结束 = 已有的一行系统消息（项目线程）/ 任务卡（会话）；汇报仍按 `background.go` 在任务结束后一次放出。进度（`task_progress`）既不入对话，也不触发读取实时集合：前端只在 `background_tasks_changed` / `task_notification` / `task_completed` 时重取 `GET /threads/:id`。
5. **前端共用同一份实现。** 项目页和文件夹页都用 `backgroundTasks()`（transcript 折叠出开始时间、命令、子 agent 步骤）+ 实时集合；详情栏和弹出面板组件不分类型，`changesLiveTasks` 提到共用模块。

## 没有做

- **详情栏里展开任务看实时输出。** 输出和子 agent 详情在顶栏弹出面板里（窄屏）；宽屏下详情栏一行只有名称、已运行时间、停止，点名称滚到对话里的调用。想看输出可以点调用卡片，或让面板也能从详情栏打开。
- **协调者工具停掉某个线程的后台任务。** 目前只有用户能停。
- **项目线程 resolve / archive 前提醒"将停止 N 个任务"。** 文件夹会话已有这个确认；项目线程的完成按钮没有确认步骤，加它是另一个交互决定。
- **项目线程在只剩后台任务时的输入框。** 线程仍是 working，输入框显示"排队"，没有回合可停。

## 被否决的做法

- **把任务数存进 `threads` 表。** 进程退出、服务重启都不会更新它，必须再做一套对账；而实时集合本来就在引擎里。
- **只在 `GET /threads/:id` 里给，卡片自己逐个去取。** N 个线程 N 次请求，且列表仍无法按任务排序/汇总（协调者页的合计就要它）。
- **任务开始、结束各发一条对话消息。** 一个 reviewer 跑一个小时会产生一串消息，正是汇报扣下机制要消灭的噪声。
