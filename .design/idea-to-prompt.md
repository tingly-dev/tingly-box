# Idea to Prompt(扩写提示词)

> 状态:**v1 已实施**(TEP-2226)。页面、可编辑指令、Playground 双向交接已上线;
> 历史在浏览器 IndexedDB(`imageWorkspaceDb.ts` 的 `ideaPrompts`),和反推、方案、素材库一样未接后端。
> 关联:`image-to-prompt.md`(兄弟页面，本页的大部分形状来自它)、`image-layout.md`(Image 入口)、`image-library.md`(描述片段)。

## 1. 它回答的问题

"我脑子里有个画面，只写得出几个词，怎么变成一段能出好图的提示词?"短提示词出来的图千篇一律;
好的提示词写清媒介、构图与镜头、光线、配色、风格，而且用目标模型喜欢的写法。以前要去聊天工具里问，再抄回 Playground。

## 2. 独立页面，而不是反推页的一个模式

| 方案 | 结论 |
|---|---|
| **独立页面，共用部件** | **采用。** 输入不同(文字 / 图片),指令不同，对模型的要求也不同(任意对话模型 / 必须能看图)。每页打开就是工作面。 |
| 反推页上加"图片 / 文字"切换 | 不要：在工作面前放了一个模式选择(原则 2),而且切换时指令框里的内容会被换掉。 |
| 一页，按输入自动判断(图、文字、图 + 文字) | 暂不：一个可编辑的指令框没法老实地服务三种情况;"图 + 文字"(风格取自图，主体取自文字)是另一个问题，见 §8。 |

## 3. 名字

- 英文 **Idea to Prompt**,中文 **扩写提示词**。与 Image to Prompt / 反推提示词成对:"输入 → 提示词";"扩写"是中文 AIGC 用户说这件事的词。
  主按钮 "Write prompt / 扩写",Playground 里的入口 "Write a full prompt from this / 把这段描述扩写成完整提示词"。
- 不叫 Expand:Playground 里 `playground.expandPrompt` 已经是"在大编辑器里打开提示词"(原则 3)。
- 图标 Tabler `IconWriting`,侧栏、主按钮、Playground 入口同一个;不用 Sparkles,那是 Playground 的"生成"按钮。

## 4. 位置

Image 侧栏分隔线之后的第一项，排在 Image to Prompt 前:两个提示词工具里，先有文字再要提示词的情况更常见。
随 Image 入口一起显隐。

## 5. 页面

与反推页同一个工作台(左栏 360–420px,右边结果，lg 上占满高度)。

- **描述**:一个文本框，任何语言，⌘/Ctrl+Enter 运行。
- **模型**:同一个 `ImageModelPicker`,同一个 `imageprompt` 场景。上次选的记在 `image.idea.model`,和反推页分开记：
  反推必须能看图，这里一个便宜的文本模型就够;规则是共用的，配一次两页都能用。
- **给模型的指令**:与反推页同一个 `InstructionsField`。默认"详细",只在改过之后才存;"从模板开始…"三个起点只是填进文本框:
  - **详细**(默认):一段英文自然语言，主体和媒介在前，然后按固定顺序补外观与动作、场景、构图与镜头、光线、配色、风格。
  - **轻度润色**:保留用户的措辞、顺序和语言，只补缺的媒介、镜头、光线、风格。
  - **标签列表**:逗号分隔的英文标签，给 SD 类模型。
  - 三者共同的底线：用户写到的元素一个不丢、不改反("at night" 被丢掉就是改写，不是扩写);补的是具体的视觉选择，不是夸奖词;
    要出现在图里的字原样保留;只输出提示词本身。用户消息是 `Description: …`,
    这样"make it darker"这种读起来像命令的描述也被当成要扩写的内容。回复同样经过 `cleanPromptReply`。
- **结果**:新的在上。每张卡上方是它来自的描述(点一下把描述、指令、模型放回左栏，原则 10),下面是可编辑的提示词、复制、留作描述片段、
  在 Playground 使用、删除;失败时重试。再点一次"扩写"就是再来一版，每版一张卡。

## 6. 交接(原则 11)

- **在 Playground 使用**:与反推页相同，`navigate('/image/playground', { state: { prompt } })`。
- **入口**:Playground 提示词框的操作区多一个按钮(框里没字时禁用),带着当前文字打开本页(router state,几个词而已，不像图片那样要绕开会话历史)。
  到了以后规则一加载完、有模型就直接运行——用户在 Playground 已经说了要做什么，再让他点一次是多余的;没有模型就只填好描述。
  用过即从 history state 去掉，刷新不会再跑一次。
- 方案页里不显示这个入口：结果回到的是 Playground,不是方案的提示词标签。

## 7. 共用部件

两页共用的东西在 `pages/image/prompt/`:`InstructionsField`(指令框 + 模板菜单 + 恢复默认)、`PromptRunCard`(提示词卡片，来源由页面传入：
反推是左边的缩略图，扩写是上方的描述)、`createPromptRunStore`(IndexedDB 集合、请求与中止、刷新打断)、`instructionStarters.ts`
(本地偏好、模板匹配)。每页只保留自己的输入、模板和用户消息的写法。

## 8. 这一版刻意不做的

- 在 Playground 提示词框里就地扩写(弹层，替换文字，可撤销),不来回跳页面。更快;页面仍留给调指令和看历史。
- 图 + 文字一起("这张图的风格，但画一座灯塔")。
- 一次出几版并排挑。
- 按 Playground 当前的生图模型自动选写法(自然语言 / 标签)。
