### 1.1 屏幕与模式清单

| 屏幕 | 区域 | 模式切换 |
|---|---|---|
| 首页 `/workspace` | 标题 + 三个同构段落（项目、工作目录、绑定），每段 3 张卡 | 无；每段有“全部 →” |
| 项目列表 `/projects` | 标题 + 3 列卡片网格 | 下划线 Tab：我的项目 / 已归档；搜索（≥6 个才出现） |
| 项目页 `/projects/:id` | 头部 + 主区（协调者对话，或线程）+ 右侧栏（Overview，或线程）；线程自带 288px 信息栏 | ① 头部“布局”菜单（Overview 3 处 × 线程 3 处 + 1 个开关）② 头部侧栏开关 ③ 下划线 Tab：线程 / 文件库 / 状态 ④ 图标分段：列表 / 竖看板 / 横看板 ⑤ 线程内：详细 / 简洁、信息栏显隐 |
| 项目设置（对话框） | 4 个 Tab：通用 / 记忆 / 环境 / 用量 | 下划线 Tab |
| 文件夹页 `/projects/folder` | 头部 + 主区（新会话或会话）+ 会话列表（有会话时并入信息栏的第一张卡） | 无布局选项；与项目页是两套结构 |
| IM 绑定 `/projects/im` | 标题 + 一张卡一个机器人 | 无 |

### 1.2 真正的问题：同一信息，在不同位置里长得不一样

摆放有很多种本身没问题；问题是下面这些“随位置变样”的地方（均已在代码里核实）：

| 信息 | 它在哪些位置怎么变 |
|---|---|
| **线程的状态 / 环境 / 用量 / 改动**（用户认为现状没问题，本方案不动；仅作记录） | 只有线程面板宽度 ≥ 880px 且用户没关时，才是线程右边的一列卡片（`RAIL_MIN_PANEL = 880`，`useInfoRail`）。1440 屏上 Overview 在侧栏时，主区约 700px，**线程在主区也看不到这一列**；线程在侧栏（360px）或浮窗（520px）时永远没有，只剩头部的几个小标签和弹层。同一份“状态”，有没有取决于窗口宽度和摆放。显隐按钮也只在宽的时候才出现。 |
| **协调者的状态** | 只在 Overview 的“状态”Tab 里（侧栏 / 窗口）；Overview 在顶栏时变成一个按钮、点开又是一个窗口；线程占了侧栏时 Overview 整个被换走，要点 ← 才看得到。 |
| **文件库** | Overview 的 Tab（侧栏 / 窗口）；顶栏时是一个按钮 → 另开一个窗口。 |
| **线程列表** | 项目页：Overview 的 Tab；顶栏：分列的 band；文件夹页：没有会话时是侧栏，有会话时变成信息栏的第一张卡。 |
| **头部的侧栏按钮** | 含义随位置变：侧栏时显隐侧栏，窗口时开关窗口，顶栏时折叠 band；文件夹页有会话时按钮直接消失。 |
| **“浮起”按钮** | 线程头部有，但 Overview 在顶栏时没有。 |
| **“布局”矩阵** | 3 × 3 里有格子被禁用（顶栏时线程不能侧栏 / 浮窗），“从 Overview 点开时浮窗”是第 4 个开关；说明藏在菜单底部。图标没有文字。 |
| **用量** | 线程信息栏、Overview 的“状态”Tab、项目设置的“用量”Tab 三份。 |
| **项目页 vs 文件夹页** | 同一个“主区 + 右栏”的想法，两套实现，规则不同。 |

另外两点是体验层面的：看板被放进 360px 的窄栏（竖 / 横两种几乎看不出区别）；首页与列表页重复，而首页没有“现在要我做什么”。

## 2. 原则

- **摆放可以多，规则只能一套。** 保留 Overview {停靠, 顶栏, 窗口} × 线程 {主区, 侧栏, 浮窗}；统一的是“放进哪个容器，内容和控件都一样”。
- **一份信息，一个组件，多个容器。** 容器只决定位置和尺寸，不决定里面有什么、怎么操作。
- **宽度只决定形态，不决定有没有。** 放得下就常驻，放不下就弹出同一份内容；不会因为窗口窄了就“没有状态”。
- **同一个按钮永远是同一个意思。**
- **保留卡片嵌套。**（用户偏好，见 visual-system §5）本方案不去掉任何外层卡片，只换卡片放的位置。
- **手机与桌面同名词。** 手机壳是 对话 / 线程 / 文件库；桌面面板的 Tab 用同样的词。

## 3. 方案 C（推荐）：保留全部摆放，统一内容与交互

### 3.0 两个澄清：协调者状态放进协调者对话；视图开关不在 Tab 行

**现状证据**：窗格最窄（`PANE_MIN = 360`）时，Tab 行只剩“线程”“文件库”，**“状态”Tab 被视图开关挤出去、点不到**（中英文都复现；Overview 窗口 460px 也很紧）：

![现状：360px 时“状态”Tab 被挤没](https://raw.githubusercontent.com/tingly-dev/tingly-box/pr-assets/pr2580/D1-squeeze-evidence.png)

**1）协调者状态不该是面板里的 Tab。** 看代码（`CoordinatorStatus`）：这个 Tab 里是协调者自己的状态（运行状态、排队、上下文占用、轮数——与线程信息栏是同一张 `StatusCard`）、模型 / effort / 会话、用量；另外还有三样**不是协调者专用**的项目级汇总：按状态统计的线程数（与线程列表的分组标题重复）、跨线程的议题与 PR、运行中的后台任务总数。把它们都叫“状态”并放在“线程”“文件库”旁边，既让它成了最先被挤掉的 Tab，也让协调者的信息离协调者的对话很远。

**2）列表 / 看板开关是“线程”视图内部的显示方式**，与“文件库”无关，却放在整个面板的 Tab 行里（只为沿用“头部一行”的样式），窄的时候互相挤。

**处理**：

![E1 协调者状态在协调者对话顶部](https://raw.githubusercontent.com/tingly-dev/tingly-box/pr-assets/pr2580/E1-status-on-coordinator.png)

- **协调者的状态放到协调者对话的顶部**（主区面包屑 `协调者 | 线程名` 之下）：折叠时一行摘要（状态 · 上下文占用 · 轮数 · 模型 · 用量），展开是三张卡 状态 / 模型 / 用量（外层一张卡、里面小卡，保留卡片嵌套）。折叠状态按浏览器记住。在 Overview 的任何容器（停靠 / 顶栏 / 窗口）里都**不再有“状态”Tab 或“状态”按钮**——顶栏模式里那个“状态”按钮和它另开的窗口一并消失。
- **线程自己的状态保持现状**（线程旁的信息栏、头部小标签与弹层），不动。
- **原“状态”Tab 里的项目级汇总**（不是协调者专用，已按下面处理）：**线程数**：列表的分组标题（`进行中 2`…）本来就带计数、点开有弹层，原“状态”Tab 里那一份是重复的，**直接去掉**，工具条只留一句 `N 个线程`；**运行中的任务总数 → 工具条里一个 chip**（点开沿用现有的活动弹层）；**议题与 PR → “线程”视图底部一张可折叠的卡**。
- **Tab 只剩内容类别**：`线程 · 文件库`（文件夹页：`会话`）；需要你处理的数量用角标 `2`，不再用“线程 · 2 个等你处理”这种长文案。
- **视图开关移进“线程”视图自己的工具条**（左：数量 / 计数条，右：`列表 | 看板`）；文件库视图有它自己的（添加文件、复制路径）。Tab 行里没有任何控件，不会被挤。
- 看板**只留一个自适应的**（已实施）：开关是 `列表 | 看板`。看板 = 每个状态一条泳道，卡片按容器宽度自动分列并换行，容器够宽（≥640px）时状态标题移到泳道左侧；窄栏里就是一列。旧的“竖看板”只在窄栏里退化成一列、与列表几乎没区别，去掉；已存的 `vertical` / `horizontal` / `kanban` 偏好都读成看板。
- **代价**：线程占着主区时，协调者状态不在眼前，点面包屑的“协调者”才看得到（以前线程占侧栏时，整个 Overview 同样被换走，要点 ← 才看得到，所以并不更差）。

### 3.3 收益与代价

**收益**：用户已经习惯的所有摆法都保留；任何位置下“状态 / 文件库 / 线程列表”的位置和长相可预期；实现上是**合并**（一个 Panel 组件，协调者状态与线程状态继续共用 `StatusCard` / `UsageCard`），代码更少。
**代价**：`overviewFloat` 偏好被并入线程浮窗；设置里的“用量”Tab 去掉；协调者状态移到对话顶部、线程占主区时看不到（点面包屑）；workdir 会话开着时不再默认带常驻右栏（3.4）。

### 3.4 线程侧板：项目线程与 workdir 会话怎么统一

用户的方向：线程占用侧栏的位置不变，只统一**线程侧板**——线程打开后，右边那块“详情”（状态 / 环境 / 用量 / 改动 / 后台任务）和旁边的列表。项目页与文件夹页（workdir）现在各有一套（均已在代码里核实）：

| | 项目线程 | workdir 会话 |
|---|---|---|
| 列表 | Overview：Tab、`列表 \| 看板`、置顶、卡片内审批（#2544）、徽标 | 一个朴素的状态分组列表，**没有**看板 / 置顶 / 卡片内审批 / 徽标 |
| 详情右栏出现的条件 | 线程面板 ≥ 880px 且没被用户关掉 | ≥ 640px，且**关不掉**（因为列表并进了它） |
| 详情右栏的开关 | 线程头部按钮，**只在够宽时才出现** | 没有 |
| 列表放哪 | Overview 的 侧栏 / 窗口 / 顶栏 | 侧栏；开了会话（宽屏）后**并成详情右栏的第一张卡**，页头的侧栏按钮随之消失 |
| 后台任务卡 | 有任务才显示 | 总显示（空也显示） |
| 线程头部 ← | 回协调者对话 | 回“新会话” |

**方案 U1（推荐）：同一个列表，同一个“详情”**

![F1a 列表侧栏开着：详情弹出](https://raw.githubusercontent.com/tingly-dev/tingly-box/pr-assets/pr2580/F1a-session-list-pane-open.png)
![F1b 侧栏收起：详情停靠](https://raw.githubusercontent.com/tingly-dev/tingly-box/pr-assets/pr2580/F1b-session-list-pane-closed.png)

1. **一个线程列表组件**：项目页的 Overview“线程”视图（工具条、`列表 | 看板`、置顶、卡片内审批、徽标）抽出来，workdir 的“会话”侧栏用同一个；差别只是分组名（会话多一个“已归档 / 空闲”）、副标题（会话带目录名）和“新会话”入口。workdir 因此白得看板、置顶和卡片内审批。
2. **列表一直在侧栏**，不再并进详情右栏；页头侧栏开关恒在、含义恒定（显示 / 隐藏列表侧栏）。线程占用侧栏位的摆放（项目页）保持现状。
3. **线程头部一个“详情”按钮，两页一样**：够宽 → 在线程右边停靠 / 收起一列卡片；不够宽（例如列表侧栏开着、主区只有约 700px）→ 在按钮下弹出**同一组卡片**。停靠阈值两页统一用一个值（建议 880px，保证对话区不小于约 590px）。按钮在任何宽度都在，“有没有详情”不再取决于窗口宽度。
4. **卡片组与顺序固定**：状态 · 环境 · 用量 · 议题与 PR · 改动 · 后台任务 · 子代理；只在有内容时出现（workdir 的“后台任务”空时也不再单独显示）。
5. **线程头部 ←**：项目回协调者、workdir 回“新会话”，都叫“返回”，位置和样式相同。

**代价**：1440 宽屏上 workdir 开会话时，列表侧栏占 440px，主区只有约 700px，详情默认是弹出而不是常驻（现在是常驻）；要常驻，用户收起列表侧栏。项目页本来就是这样。

**方案 U2（不推荐）：列表并进详情右栏**（把 workdir 现状推广到项目页）：线程打开时，项目页的 Overview 侧栏消失，列表成详情右栏的第一张卡。问题：项目页的列表带看板和置顶，看板需要宽度，装进一张 288px 的卡里没法用；并且会改变“线程占用侧栏 / 主区”的现有摆放，与“位置不变”冲突。

## 4. 备选：A（收窄成 Tab）与 B（只修剪）

在用户澄清“灵活性是优点”之前提出，保留作为参照；只有当以后决定**减少摆法**时才相关。
