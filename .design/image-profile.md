# 图像 Profile

> 状态：**前端原型，存储未接入**。Profile 存在模块内存里（`frontend/src/pages/image/profiles/imageProfileStore.ts`），
> 用 mock 数据预置了三个；刷新页面就会丢失。生成本身走的是现有链路，没有改动。

## 1. 是什么

一个 Profile 把**一项持续的工作**固定下来：参考图（用户自己选，受单次上限约束）、
这项工作用到的几条提示词、以及模型 / 尺寸 / 质量 / 数量。它的页面就是 Playground，
只是这些东西已经就位。

## 2. 为什么不是 `@` 引用（上一版原型）

上一版是"设定 + `@name` 组合"：角色和风格分开存，生成时用 `@` 拼起来。被否掉的原因有三个：

- **参考图上限是硬约束。** 组合多个设定必然超出 5 张，系统只能替用户决定带哪几张，
  然后再用一条警告解释这个决定。选哪几张图本身就是这项工作的一部分，应该由用户在 Profile 里选好，而且只选一次。
- **心智不对。** 用户要的是"把一项工作固定下来"，而不是"每次临时拼素材"。
- **太密。** 引用面板、预算、截断提示、prompt 预览，全都堆在 Playground 左栏里。

代价是失去了"任意角色 × 任意风格"的自由组合，用"新建一个 Profile"来覆盖。

## 3. 形态（对齐 Claude Code profile）

- 侧栏 Image 下：Playground（默认）→ 每个 Profile 一行（封面缩略图 + 名称，不再重复写 "Profile"）→「新建 Profile」→ Image API。
- 路由 `/image/profile/:id`，复用 `ImageGenPlaygroundCard`，通过 `profile` prop 区分。
  没有新增面板。
- **一个 prompt 框，多条提示词。** Profile 里存了几条提示词，框上方是一排文字标签，点哪条框里就换成哪条。
  在框里改的就是当前这条，各条互不影响。标签本身就起到标题的作用，所以框不再显示「提示词」字样。
  - 没起名的提示词，标签显示它开头的几个字，打字时会跟着变；只有空的才显示"提示词 N"。
    双击可以起名，清空名字就回到自动标签。
  - 当前标签悬停时出现 ×（至少保留一条）。删除不弹确认框，而是在同一行右侧给出「已移除…撤销」，8 秒后消失。
- 上一版原型里有一个"固定描述 + 这一次"的双框，被否掉了：两个框太重，而且多数时候
  用户要的是在几条完整的提示词之间切换，而不是拼接。
- **自动保存**：参考图、提示词、参数改了就存回 Profile，和 Claude Code profile 页一致，不存在"未保存"状态。
  每次保存后，标题旁会淡入淡出一个「已保存」，用来代替一句常驻的说明文字。刚打开页面、内容没有变化时不写入，也不提示。
- **历史按 Profile 隔离。** 生成历史和导入的图片仍然是同一个会话存储（内存 + IndexedDB），
  但每条记录带有 `profileId`（未设置 = 默认 Playground），每个页面只显示自己的那部分；
  「清空」只清当前页面；删除 Profile 时一并删除它的历史。副标题和默认 Playground 一样显示输出目录。
- 「复用这次请求」时，如果这次的 prompt 和某条已存的提示词一致，就切到那条标签上。
- **创建**：
  - 主路径：在默认 Playground 里调好一次，点「存为 Profile」。当时的 prompt 变成它的第一条提示词，
    Profile 的名字默认取 prompt 开头几个字，跳过去后标题处于重命名状态。
  - 侧栏「新建 Profile」：直接建一个空的，跳到它的页面，标题处于重命名状态，中间没有对话框。
- 删除在标题栏右侧，需要确认。已经生成的图片仍留在输出目录。
