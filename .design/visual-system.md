## 0. 结论先行

1. **先定规范，再整体升级。** 现在的问题不是某一页难看，而是没有一套能约束所有页面的规则：同一件事（选中、状态、卡片、标题）在每页各写一遍。先把规范写下来、落成主题里的 token 和少量组件，再一页页迁移；顺序反过来只会多一套新的不一致。
2. **规范收在一个地方。** 现在 5 套主题各自手写约 25 个 MUI 组件的覆盖（约 460 个颜色字面量），改一处视觉要改 5 遍。先把主题改为「语义 token → 一个组件工厂」，不改外观；之后任何视觉调整都只改 token。
3. **方向：安静、统一的工作台。** 中性的底，主体（规则、凭证、会话）当视觉锚点；颜色只放在标记（点、图标）上，文字保持中性。导航（rail + 侧栏）**保留现在的实心强调色**选中，品牌蓝的其余用途收到每个区域唯一的主操作上。Projects 页已经按这个方向收过一轮，是现成的参照。
4. **重点是统一，不是换风格。** 导航观感、密度保持不变；变化集中在：一套 token、字号层级、圆角 / 阴影、状态用色、页头和容器结构。
5. **每一步都是可单独合并的小 PR，带截图。** 下线 sunlit → token 重构（看不出变化）→ 字号 / 圆角 / 阴影 / 西文字体 → 选中与强调 → 状态与配色 → 页面骨架 → 去掉卡片套卡片 → 暗色修复 → claude / ds 预设 → lint 守门。

## 1. 现状审计

### 1.1 主题结构：同一套规则写了 5 遍

- `packages/ui/src/theme/` 有 5 套主题（light / dark / sunlit / claude / ds），每套都是 `palettes/<x>.ts` + `components/<x>.ts`。10 个文件里共约 **460 个十六进制 / rgba 字面量**（组件覆盖约 250 个，调色板约 210 个）。
- 每套主题都重写同一批组件：`MuiOutlinedInput`、`MuiButton`、`MuiCard`、`MuiMenu`、`MuiTooltip`、`MuiTabs`、`MuiDrawer`、`MuiDialog`…… 约 25 个，值是写死的颜色（如 light 的边框色 `#e2e8f0` 在组件文件里写了 6 次、主色 `#2563eb` 写了 5 次），而不是从 palette 推导。
- `index.ts` 用浅合并 `{...baseComponents, ...components}`：某个主题一旦覆盖 `MuiButton`，`base.ts` 里同名的规则整块失效。
- 死代码：5 个主题里都有 `MuiListItemButton` 的 `.nav-item-active` 规则，但没有任何组件用这个 class（侧栏选中样式实际在 `Sidebar.tsx` 里内联）。
- 后果：`theme.md` 里两次修复（DS 主色、禁用态）都要逐个主题改；本次任何视觉调整同样要 ×5。

### 1.2 字号与字重：小字太小，正文是灰色，层级太多

基于 `base.ts` 的 typography 和全仓统计：

| 问题 | 证据 |
|---|---|
| `caption` 只有 **10.4px**（`0.65rem`），却是第二常用的字体变体 | `variant="caption"` 407 处；侧栏栏目名、表单 label、元信息都落在 10–11px |
| `body1` / `body2` 默认颜色是 `text.secondary` | 正文整体发灰，靠每个调用处再写 `color: 'text.primary'` 拉回来 |
| `h6`（14px）与 `body1` 同字号，只靠字重区分 | 标题层级在 14px 上挤成一团 |
| 字重 5 档 | `600`×256、`500`×79、`700`×23、`bold`×8、`650`×7（主题标题也是 650） |
| 绕开 `fontSizes` 的字面量 | `13`、`15`、`0.875rem`、`1.05rem`、`0.9375rem`、`0.8125rem` 等仍有上百处 |
| 页面标题 22px / 650 | `PageHeader` 用 `h3`；Agent 页标题在 Linux 上又粗又宽（见 §1.8） |

### 1.3 选中与强调：蓝色太多，抢了主体

- 导航的实心选中（rail 当前项、侧栏当前行）是用户习惯的样式，**保留**（§5 决定 1）。问题不在它本身，而在页面里还有更多实心蓝和它抢：
- 一屏里有多个实心主按钮：工作区首页三个分区各一个（新建项目 / 添加工作目录 / 绑定聊天），加上导航两块，一屏 5 块实心蓝；Agent 页 Slots 的当前项、机器人页的能力标签也是实心蓝。
- 同一个「选中」有四种写法：rail 在 `ActivityBar.tsx` 内联实心蓝，侧栏行在 `Sidebar.tsx` 再内联一份（带给品牌图标垫白底、清 filter 的补丁），设置齿轮用 `action.selected` 浅底，`@tingly/ui` 的 `navRowSelectedSx` 是第四份（Projects 侧栏在用）。外观接近，实现各写各的，改一处漏三处。
- 主按钮是渐变（`buttonVariants.ts`），与其余扁平的控件不是一个时代。

### 1.4 颜色使用：状态色当装饰

- 机器人页（`components/bot/BotTable.tsx`）：每行一个绿色实心「On」徽标（和旁边的开关重复，即 ux-review F4），两个蓝色实心能力标签（像按钮，F3），刷新 / 编辑图标蓝色、删除图标红色——5 行就是 25 个彩色元素。
- Guardrails：「Blocked」「Masked」计数是红 / 橙实心徽标，与「Allow」的描边徽标不是一套。
- 凭证表：开关绿色、到期时间前的时钟也是绿色——「正常」不需要颜色。
- Projects 已经定下「颜色只给『需要你』（琥珀）和『失败』（红）」的预算；宿主页面没有这条规则。

### 1.5 结构：卡片套卡片，页头各写各的

- **卡片套卡片**：
  - 凭证页：`Surface`（带边框）→ 表格容器（带边框、圆角）→ 每行的操作按钮组（又一个描边框）。
  - Agent 页「模型规则」：外层卡片 → 每条规则一张卡片 → 每个路由节点一张卡片，三层边框。
  - 机器人页：外层卡片 → 灰底表头的表格。
  - 帮助页：每个折叠项都是一张独立的卡片。
- **页头不统一**：凭证、机器人、帮助、Guardrails 用 `PageHeader`（标题 + 副标题 + 分隔线）；Dashboard 没有标题，第一行就是筛选条；系统页没有页标题，每个分区自己是一张带大标题的卡片；Image 实验台的标题在卡片里面；Agent 页标题和状态挤在一行、没有分隔线。
- **内容宽度**：工作区首页居中限宽（约 1000px），其余页面铺满。
- **圆角三套**：`radius.ts` 定义了 12 / 8 / 6，但 `Surface` 和 `UnifiedCard` 用 `borderRadius: 2`（=16px），`MuiCard` 是 12，按钮和输入框 6，Chip 4；代码里 `borderRadius: 1`×107、`2`×89、`1.5`×39、`3`×21，用 `radius.*` 的只有 70 处。
- **阴影**：`MuiCard` 带阴影（工作区卡片看起来浮着），`Surface` / `UnifiedCard` 不带；调用处另有 62 个 `boxShadow` 字面量。

### 1.6 暗色模式

- **彩色品牌图标变成白块**：`BrandIcons.tsx` 在暗色下对彩色 logo 做 `grayscale(100%) brightness(1.6)`，有底色的 logo（Codex、WorkBuddy、微信、企业微信、Telegram）被压成白色方块 / 圆块，在 Agent 侧栏和机器人页最明显。
- 主内容区滚动条用 `grey.100 / grey.300`（`layout/styles.ts` 的 `mobileContentSx`），只适配亮色。
- 禁用的主按钮两种模式不一致：亮色下几乎看不见（Image 实验台「生成」），暗色下看起来像可点。

### 1.7 次要主题

- sunlit 的 `background.default` 是 `transparent`，paper 是半透明白，加一层渐变；ds 也有背景渐变。实际效果是 rail / 侧栏与内容区的底色关系每套主题都不同。
- 5 套主题意味着每个视觉改动都要验证 5 次；若没有 token 层，这个成本会一直存在。

### 1.8 字体（环境相关，需确认）

`fontSans` 里没有 Linux 上常见的字体（Inter / Noto Sans / Cantarell），在 Linux 和 WebKitGTK（Wails）下西文会落到 DejaVu Sans：字面宽、粗体很重。截图环境就是这种情况，所以截图里的粗重感有一部分来自字体；macOS / Windows 上会轻一些。是否打包一款西文字体是待定问题（§5）。

### 1.9 已经做对的部分（保留）

- `@tingly/ui` 已有 `fontSizes`、`radius`、`elevation`、`status.ts`（固定的状态色）、`nav.ts`（导航行几何）、`PageHeader` / `Surface` / `EmptyState`——基础件都在，问题是没被强制使用。
- Projects 包几乎没有颜色字面量（全包 1 个 hex），`fontSizes` 用得最多，状态语言已经定过一轮（`projects-visual.md`）。
- 路由图（规则 → 节点）是 Tingly Box 的辨识度，保留；本次只调它外面的容器和字体，不改图本身的表达。

## 2. 目标规范

规范只做两件事：**定 token**（数值），**定用法**（什么时候用什么）。数值落在 `@tingly/ui/theme`，用法写在这里并在 PR 评审中检查。

### 2.1 字号（基准 14px，只用 400 / 500 / 600 三档字重）

| Token | 尺寸 / 行高 / 字重 | 对应变体 | 用于 |
|---|---|---|---|
| page-title | 20 / 28 / 600 | `h3` | 页标题（`PageHeader`） |
| section-title | 16 / 24 / 600 | `h4` | 分区标题（「模型规则」「服务器状态」） |
| title | 14 / 20 / 600 | `h6` | 卡片标题、行标题 |
| body | 14 / 22 / 400，`text.primary` | `body1` | 正文 |
| body-sm | 13 / 20 / 400，`text.secondary` | `body2` | 次要正文、表格单元 |
| meta | 12 / 18 / 400，`text.secondary` | `caption` | 元信息、表单说明、表头 |
| micro | 11 / 16 / 500 | `overline` / 徽标 | 只用于徽标、计数、rail 标签 |
| code | 13，等宽 | — | URL、Key、命令、模型名 |

`fontSizes` 同步收为 `micro 11 / sm 12 / md 13 / base 14`，旧的 `xs`、`lg` 先作为别名保留，迁移完删除。

### 2.2 颜色（语义 token，每套主题只填这一张表）

| Token | Light | Dark | 说明 |
|---|---|---|---|
| `bg.canvas` | `#f6f7f9` | `#07090f` | 页面底 |
| `bg.surface` | `#ffffff` | `#11141c` | 卡片、表格、对话框 |
| `bg.subtle` | `#f3f4f6` | `rgba(255,255,255,.04)` | 代码块、分段控件底、表头（可选） |
| `bg.raised` | `#ffffff` | `#181c26` | 菜单、弹层 |
| `border` | `#e6e8ec` | `rgba(255,255,255,.09)` | 唯一的常规边框色 |
| `border.strong` | `#d4d7dd` | `rgba(255,255,255,.18)` | 输入框、描边按钮 |
| `text.primary / secondary / tertiary` | `#111827 / #5b6472 / #9aa1ac` | `#f3f5f9 / .72 / .45` | 三档文字 |
| `accent` | `#2563eb` | `#3b82f6` | 主按钮、链接、焦点环 |
| `accent.soft` / `accent.ink` | `accent` 9% / `accent` | `accent` 18% / `#9ec1ff` | 内容区选中底 / 选中文字（导航不用，见 §2.4-2） |
| 状态色 | 沿用 `status.ts` 固定集 | 同左 | 只用在点和图标上 |

组件覆盖（`MuiButton`、`MuiOutlinedInput`、`MuiMenu`……）由一个 `createComponents(tokens)` 生成，主题文件里不再出现组件级颜色。

### 2.3 形状、阴影、间距

- 圆角三档：**12**（卡片、面板、对话框）、**8**（按钮、输入框、行、分段控件、Tab）、**6**（徽标、Chip、行内代码）；圆点用 50%。`Surface` / `UnifiedCard` 从 16 收到 12，按钮和输入框从 6 改到 8，Chip 从 4 改到 6。
- 阴影：页面上的面一律平面 + 1px `border`；阴影只给浮层（菜单、弹出层、对话框、Tooltip），用 `elevation.ts` 的三档。
- 间距：4px 网格；页面左右 24（md 以上）；分区之间 24；卡片内边距 20（窄屏 16）；表格行高 44–48；侧栏行几何沿用 `NAV_ROW_SX`。
- 宽度：表格、路由图、看板铺满；表单和设置类页面正文限宽 960，标题行仍铺满。

### 2.4 用法规则

1. **一个区域一个实心主按钮。** 其余用描边或文字按钮。页头的主操作和分区里的主操作不同时出现。
2. **两种选中，各用一处。** 导航选中（rail、侧栏、Projects 侧栏）= **实心主色**，保持现状，收为一份 `navRowSelectedSx`（含品牌图标垫白底）。内容区选中（分段控件、Tab、可选列表行、筛选 Chip、Slots）= 浅底 + 主色文字（`accent.soft` + `accent.ink`）。实心主色只用于导航选中和主按钮。
3. **颜色只给标记，文字保持中性。** 状态 = 点或图标 + 中性文字。实心彩色徽标只用于「需要你处理」和「失败」的计数。「正常 / 已启用」不上色。
4. **危险操作不预先标红。** 行内的删除图标是中性色，悬停和确认弹窗里才是红色。
5. **不套卡片。** 页面 → 分区（分区标题 + 一个容器）→ 容器内用分隔线或行；容器里不再出现带边框的子卡片。例外：路由图节点、看板卡片这种「内容本身就是卡片」的场景。
6. **每页都有页头。** `PageHeader`（20/600 标题、可选副标题、右侧操作）；Dashboard、系统、Image、Agent 页补齐或改用它。
7. **不在调用处写颜色和字号。** 颜色用 palette / token，字号用变体或 `fontSizes`，圆角用 `radius`；主题目录以外的 hex / rgba 字面量和数字字号由 lint 拦下（例外需注释说明，如图表配色、品牌色）。

## 3. 原型

临时改动，未提交；前后对比图放在本文所在 PR 的描述里。

- **v1**：导航也改成浅底选中。**未采纳**——用户希望导航保留原来的强调色。
- **v2**（以此为准）：导航不动；只改主题层（字号、圆角、阴影、主按钮去渐变）、凭证页去掉外层卡片、机器人页状态与能力标签去色。

v2 可以看到：

- 只改主题层（没动页面布局），正文和元信息可读性明显提高，卡片变平，Agent / 凭证 / 工作区页整体更安静，导航观感与现在一致。
- 机器人页去掉 On 徽标和实心能力标签后，状态仍然一眼能读出（开关 + 绿点 / 虚线标签），彩色元素从每行 5 个降到 3 个（开关 + 两个小绿点）。
- 凭证页去掉外层卡片后少了一层边框，表格直接贴在分区标题下面。
- 原型没有处理：Agent 页规则的三层边框、页头统一、暗色品牌图标、次要主题。这些属于 §4 的后续步骤。

## 4. 分步实施（每步一个 PR，可单独合并，可单独回退）

每个 PR 都附固定页面集（Agent / 凭证 / Dashboard / 机器人 / 系统 / 工作区 / 项目页）light + dark 的前后对比截图，图片推到 `pr-assets` 分支 `pr<编号>/` 下并嵌进描述。

| # | PR | 内容 | 用户可见变化 | 风险 |
|---|---|---|---|---|
| 0 | 规范（本文） | 审计 + 目标规范 + 计划 | 无 | — |
| 1 | 下线 sunlit | 删 palette / components / 图标 / 三语文案 / `isSunlit` 分支；存过 `sunlit` 的用户回落到 `light`（而不是 `isThemeMode` 失败后的 `system`） | 主题菜单少一项 | 低 |
| 2 | 主题 token 化 | 每套主题收为一张语义 token 表；`createComponents(tokens)` 生成组件覆盖；删除 `.nav-item-active` 死代码 | **无**（4 套主题逐页像素对比） | 中：改动面大，但纯机械 |
| 3 | 字号 / 圆角 / 阴影 / 西文字体 | 按 §2.1 / §2.3 改 typography、`fontSizes`、`radius`、按钮 / 输入框 / Chip / Card 覆盖；`Surface` / `UnifiedCard` 圆角 12；打包 Inter（woff2，Latin 子集，`font-display: swap`），`fontSans` 首位改为 Inter，中文继续走系统字体 | 全局：字更清楚、卡片变平、西文观感跨平台一致 | 中：`caption` 从 10.4 变 12，需逐页查溢出 |
| 4 | 选中与强调 | rail / 侧栏 / 设置齿轮 / Projects 侧栏统一到一份实心 `navRowSelectedSx`（外观不变，删掉内联副本）；内容区选中（Slots、分段控件）改浅底；主按钮去渐变；每区域一个主按钮（工作区首页等） | 导航不变；页面内实心蓝变少 | 低 |
| 5 | 状态与配色 | `@tingly/ui` 加 `StatusDot`；机器人页、Guardrails、凭证表按 §2.4-3/4 去色 | 机器人 / Guardrails / 凭证 | 低 |
| 6 | 页面骨架 | Dashboard、系统、Image、Agent 页使用 `PageHeader`；按 §2.3 定内容宽度 | 页头一致 | 低–中：Agent 页头有状态行，需保留信息 |
| 7 | 去掉卡片套卡片 | 凭证页、机器人页、帮助页、Agent「模型规则」（规则改为一个容器里的分隔行，路由图节点保留） | 层级变清楚 | 中：Agent 页是主页面 |
| 8 | 暗色修复 | 品牌图标：彩色 logo 暗色下不再灰度提亮；滚动条跟随主题；禁用主按钮两种模式对齐 | 暗色 | 低 |
| 9 | claude / ds 预设 | 两套主题收为「主色 + 底色」token 预设 | 次要主题 | 低–中 |

## 5. 决定（2026-11-12，用户确认）

1. **风格方向：安静、统一。** 重点是统一工作，不是换风格。**例外：导航（rail + 侧栏）保留原来的实心强调色选中**——用户习惯了；v1 原型里的浅底导航不采纳。
2. **暗色模式：在范围内。** 与亮色共用一套 token，PR 8 修已知暗色缺陷。
3. **主题：下线 sunlit。** 保留 light / dark / 跟随系统，claude / ds 作为「主色 + 底色」预设保留（PR 1、PR 9）。**DeepSeek 的雾状渐变背景保留**——那是这套主题的设计本身（2026-11-13 确认），收成预设时只收颜色，不动背景。
4. **字体：打包西文字体（Inter）。** 中文继续用系统字体。`@fontsource-variable/inter`（SIL OFL 1.1，与 MPL-2.0 及商业授权兼容：可随软件分发，不得单独出售，需附版权与协议），协议全文随 UI 分发在 `/licenses/Inter-OFL.txt`，并记入根目录 `NOTICE`。
5. **密度：先保持当前。** 行高、侧栏行高不动；以后若要收紧，只改 token。
