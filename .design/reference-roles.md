# 参考图用途(Reference Roles)

> 配套阅读:`sketch-canvas.md` §4.10(骨架 + 提示词建议插槽的由来)。

## 问题

多张参考图时,模型要自己猜哪张是主角、哪张只借一个表情。猜错的代价是具体的:
把表情参考图里那个人的**长相**抄到角色身上,把服装参考图里的**姿势**也一并带走。

这件事是从"表情怎么给模型"一路讨论下来的。试过的路和结论:

| 路 | 结论 |
|---|---|
| 把表情画进 OpenPose(脸部 70 点) | 全身构图里脸只有几十像素,点糊成一团 |
| 自定义"表情线稿脸"(参数化眉/眼/嘴 + 纹路) | 做了样稿:能分出类别,但质感远不如一张真参考图;关键点版本连人都分不清 |
| 写实参数化人脸(FLAME 等) | 许可(非商用)和重资产,不做 |
| 动漫:VRM(开放标准,自带表情 + 骨骼) | 值得,但是单独立项的规模,且会重新引入"模型把渲染的角色当内容"的问题 |
| **真参考图 + 说清楚它是干什么的** | ✅ 写实动漫都覆盖,不需要任何编辑器 |

所以要补的不是"表情工具",而是**让用户能说出每张参考图的用途**。

## 设计

- **用途是图的属性**(`ReferenceImage.role`),和蒙版一样:跟着图排序,图删了它也走。
  重画草图保留原用途。
- 六种:角色 / 表情 / 姿势 / 服装 / 风格 / 场景,外加"不指定"。菜单里每项带一句
  "只取什么"的说明。
- **显示为缩略图下面的一行小字**,不是缩略图上的第四个按钮:缩略图上已经挤了三个,
  而用途首先是用来**读**的("这张是表情"),其次才是用来改的。未设置时是淡色的
  "用途",设置后就是用途名本身(原则 5)。
- **默认值**:带人偶的草图默认是"姿势"(那是它唯一可能的用途);其他图默认无——
  给照片猜"角色"猜错和猜对一样多,错的标签比没有标签更糟。`undefined` 表示没设过
  (走默认),`null` 表示用户**主动**去掉了,默认值不许悄悄加回来。

## 模型怎么知道

**不自动写进提示词**,走 `sketch-canvas.md` §4.10 的建议插槽:每张有用途的图在提示词
下方给一个 chip(`表情说明 · 图 2`),悬停看全文,点击追加成独立一段,用过即消失。

每句话都包含两半:**取什么**和**不取什么**。"仅作表情参考"而不说"不要沿用长相",
恰好就是身份泄漏发生的方式。

带人偶的草图用途是"姿势"时,沿用原来那句更具体的(骨架 / 人偶 + 机位文字);标成
别的用途,就换成那个用途的句子。chip 的 id 带着用途,改了用途会重新出现。

## 已知限制

- 插入的句子里写死了图号。插入之后再拖动排序,句子里的编号不会跟着变——而 chip 会
  按新编号重新出现,两句并存。要解决得让提示词引用图而不是编号,暂不做。
