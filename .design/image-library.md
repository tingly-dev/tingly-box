# 图像素材库（Image Library）

> 状态：**前端原型，存储未接入**。素材存在模块内存里（`frontend/src/pages/image/library/assetStore.ts`），
> 用 mock 数据预置；刷新页面就会丢失。目标是把素材库落在图像输出目录上（见 §5）。

## 1. 为什么需要

在此之前，一张图只有三种下场：**正在用**（在参考图行、某个方案、历史里）、**是个文件**（输出目录，界面管不了）、
**删了**。缺一个"留着，但这会儿没在用"的地方：图片没有身份，同一张图放进两个方案就是两份拷贝；
想留下的结果只能靠"历史还没被清掉"来保留。

## 2. 和配置方案、历史的关系

```
素材库（留下来的）   ←  引用  ←   配置方案（怎么用）
      ↑ 留下                        ↓ 生成
历史（发生过的，可清空）  ←────────────┘
```

- **配置方案是工作上下文**：哪些图、哪些提示词、什么参数，用来完成一项工作。
- **素材是材料**：有身份，可以被多个方案用到。方案**引用**素材，不**拥有**素材。
- **历史是发生过的事**，可以清空。

## 3. 规则

- **用户选过的才进库，看过的不进。**
  - 加进方案的参考图自动进库（已经挑过了，不用再点一次保存）。
  - 生成结果默认只在历史里，在大图预览中点「留下到素材库」才进库。
  - 默认 Playground 里临时用的参考图不进库。
- **图片按引用。** 身份就是图片本身（原型里是 data URL）：从素材库选的参考图和素材是同一张图，
  所以能算出"用在哪些方案"。同一张图留两次，仍是同一个素材。
- **描述片段按拷贝。** 插进提示词后就是那条提示词自己的文字，改动不会影响别处。方案标签页里的提示词仍归方案所有。
- **删除先说后果。** 删除素材时在对话框里就地说明"会从 N 个方案中移除，文件同时删除"，确认后才执行。
  这和「从历史移除」「从方案移除」是三种不同的操作。

## 4. 入口

- 侧栏 Image 下，分隔线之后：「素材库」，在方案列表之外，因为它跨方案。
- 参考图行的来源按钮：浏览 / 粘贴 / 手绘 / **素材库**。有图时四个按钮收窄，保持一行。
- 提示词框右侧：「插入描述片段」，插在光标处，必要时补一个逗号。菜单底部可以去管理片段。
- 大图预览：「留下到素材库」，已留下时显示对勾。

## 5. 命名

中文叫「素材库」，片段叫「描述片段」：侧栏已经有一个顶级栏目「提示词」（编码 agent 的提示词和技能），
所以避免再出现一个"提示词"。英文为 Library / Snippets。

## 6. 接入时要补的

- 存储落在图像输出目录：生成结果在 `outputs/`，参考图在 `refs/`，片段可以是 `snippets/*.md`。
  这样"是个文件"和"被管理"是同一个状态。需要处理用户在外部删改文件的情况（扫描或文件监听）。
- 身份改为内容哈希或文件路径，不再比较 data URL。
- 删除改为移入回收站。
- 历史里的生成结果可以考虑超期自动清理：有了「留下」，历史就可以放心地是临时的。
