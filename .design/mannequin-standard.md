# 人偶标准(Mannequin Standard)

> 配套阅读:`sketch-canvas.md` §4(人偶在产品里是什么)、`pose-from-image.md`
> (从照片导入)。这份文档只回答一件事:**人偶应该长成什么样,以及为什么**。
>
> 事实源:白模是 `frontend/packages/mannequin/src/model/makehuman.ts`(由
> `scripts/bake-makehuman.mjs` 生成,不要手改);骨架 `BONES`(`skeleton.ts`)从白模
> 自己身上量出来;蒙皮在 `body.ts`。下面的数值是说明,不是副本——对不上时以代码为准。

## 0. 这份标准是怎么来的

前后返工了四轮,每一轮都是"我觉得这样好看"。第四轮的反馈是一句很准的话:
**"应该多看看行业里面大家是怎么做的,特别是美术相关的"**。去看之后,有两条
我自己拍脑袋定下的结论被直接推翻:

1. **关节应该收窄,不是鼓起来。**我一直在把球画得更好看,方向从一开始就错了。
2. **头不是太大,是太小。**上一轮我把头缩了一档,人直接变成 8.7 头身——那是
   时装插画的比例,不是人。

教训写在这里,而不是留在对话里:**对着参考图调参数是没有收敛点的,对着画法
的规矩调才有。**

## 1. 比例:Loomis 八头身

以头长为 1,从头顶往下数:

| 位置 | 头数 |
|------|------|
| 下巴 | 1 |
| 乳线 | 2 |
| 脐 | 3 |
| 耻骨(**正中**) | 4 |
| 膝 | 6 |
| 脚底 | 8 |

肩宽约 **2 个头**,胯宽约肩宽的 **3/4**(约 1.5 个头)。这套是画人体的通用基准,
不是风格选择:偏离它的人偶,第一眼就会被读成"比例不对",而看的人往往说不清
哪里不对。

实现上比例落在 `BONE`(骨长,任意单位、最后归一化)。检验方式是量出来的
头身比,而不是看着像不像——**人偶的比例是一个可测量的量**。

## 2. 白模:用现成的人体基础网格,不自己雕

**这一条推翻了这份文档之前所有关于"形体"的章节。**

前五轮都在自己造身体:先是球和锥柱拼的木偶,再是手调截面的"雕刻"扫掠体。每一轮都比
上一轮好一点,每一轮读起来都还是玩具——因为**雕一个人体是一门手艺,一张半径表不是**。
用户的原话:"应该寻找更好的建模方案,建立更好的人偶白模,而不是自己折腾"。

现在的身体是 **MakeHuman 的基础网格(hm08)**:

- **许可**:MakeHuman 自 1.1.0 起把资产(基础网格、targets、骨架)以 **CC0 1.0** 放进
  公有领域;它的**代码**是 AGPL,我们一行都不用。数据取自 npm 上的 `makehuman-data@0.0.2`
  (2016 年导出的 hm08,和 1.1 的 CC0 资产是同一个网格;那个 npm 包的 readme 自称
  "AGPL 派生",以上游的 CC0 声明为准——这是一个已知的、记录在案的判断)。
- **两种体型**:用 MakeHuman 自己的宏 target——三个人种平均的 `*-female-young` /
  `*-male-young`,外加 **ideal proportions**(MakeHuman 的"艺术理想比例",正是绘画人偶
  要的,而不是平均人)。实测男性约 7.6 头身。
- **白模而不是裸体**:乳头用 `nipple-size-min` + `nipple-point-in` 压平,其余(生殖器
  helper、眼球、牙齿、关节立方体等辅助几何)全部不要,只留 `body` 材质的面。这既是人偶
  的样子,也让发给图像模型的草图不像一张未着装真人的照片(会触发审核)。
- **体量**:13,380 顶点 / 26,756 三角面,两种体型的位置量化成 int16,一共约 560 KB 的
  生成模块,只进图像页的懒加载 chunk(不在首屏 modulepreload 里)。

### 美术人偶,不是人

用户要的是参考图那种**美术人偶**,不是写实人体(写实版做过一轮,有真人脸)。所以烘焙时把
MakeHuman 的人风格化(`stylise`,全部离线,运行时仍是一层普通的皮):

- **蛋形头**:Loomis 的头——颅骨椭球 + 收窄的下颌,尺寸取自模型自己的头顶到下巴,沿颈部
  前倾的轴摆正(竖直摆在前倾的脖子上会读成仰头)。头部顶点沿射线投到蛋面上,按皮肤权重和
  脖子过渡。
- **把折叠抹平**:投影保留旧拓扑,嘴、眼窝、耳朵会塌成叠在一起的褶;在蛋面上做松弛
  (与邻点平均 → 投回蛋面,反复)把它们摊开,剩下仍然朝里的三角形删掉。
- **手脚简化、全身轻度平滑**:Taubin 平滑(不缩水),手脚、锁骨/斜方肌处额外几轮。

### 结构线

参考图里每个人偶都有的线:**关节的分节环**(颈、肩、肘、腕、腰、髋、膝、踝)和**头上的
十字**(中线、眼线)。每条线是静止网格被一个平面切出来的,存成"网格边上的点"(两个顶点 +
一个比例),所以运行时贴着皮肤走,零额外绑定。用屏幕空间的粗线画,沿法线抬起一点不被皮肤吞掉。

### rig 还是我们的

16 个关节仍然是姿势的唯一表达;变的只是"关节 → 图像"这一段。网格被蒙皮到 **12 个段**
(骨盆、胸廓、颈、头,四肢各两段),MakeHuman 163 根骨头的权重按表折算到这 12 段
(脊柱几节在骨盆和胸廓之间按比例分;手跟前臂、脚跟小腿走,和任何关节木偶一样)。

每段的朝向只从关节算:轴是骨头方向,扭转从弯曲的那个关节读——弯着的肘说明前臂朝哪,
直着时退回身体正面,两者**混合**而不是切换,所以不会翻。静止姿态和任意姿势用**同一个
函数**算朝向,两者之差就是关节描述的那个旋转。骨长不等时(旧草图)沿骨头拉伸,皮肤仍然
贴着关节。

**骨架是从网格上量出来的**,不是先写一张表再把身体凑上去:`BONES` 直接读白模的关节,
所以姿势库用的骨头就是网格被绑定的骨头,蒙皮不会被拉伸。

### 一份几何

(结构线是装饰,不参与命中测试。)

渲染、命中测试、可见边界都用同一个蒙皮后的表面(`figureSurface`,按人偶对象缓存):
命中测试是投影后的三角形,`figureVisualBounds` 是投影后的网格包围盒(手指、脚趾都在
里面)。没有第二张"能抓的"表。

### 相机必须和 `projectionOf` 逐像素一致

蓝色手柄是从 `projectFigure` 画的,身体是 WebGL 画的,两者对不上就是灾难。所以 3D
相机就是 `projectionOf` 描述的那台针孔相机:针孔在人偶自己的锚点、焦距一个
`distance`、画布是这台相机视野里的一扇**偏心的窗**(`setViewOffset`)。

### 一个共享的 WebGL 上下文

所有绘制都进同一个离屏 WebGL 画布,再 `drawImage` 到调用方的 2D 画布上;姿势库四十多个
缩略图共用一个上下文。实测(软件 GL)44 个缩略图连蒙皮约 0.5 秒。没有 WebGL 的地方退回
平涂的投影三角形。

## 3. 脖子向前倾,角度从模型读

`neckForward` 从白模静止姿态里量(女 ≈14°、男 ≈8.5°,相对脊柱)。头是绑在**它的**脖子
上的:姿势里的脖子比网格直,脸就会朝天看。

这里也踩过一个符号坑:`buildPose` 里那次旋转一直是**往后**倒的。木球脑袋上看不出来,
换成真脸之后一眼就看出"所有人都在仰头"。现在正角度往前。

## 4. (历史)手造形体

球窝/铰链、截面表、旋转体胸盆这些章节已删,原因见 §2。留下的教训只有一条:
**能用现成的、专业做出来的东西,就不要在代码里雕。**

## 5. (已删)折回去的肢体拆成两片

2D 时代肢体折回自己身上会让单条轮廓自交、填出一片鳍,所以要在折点拆成两片按深度排。
真 3D 里两根锥柱本来就是两个物体,这个问题**不存在**。保留标题是为了说明:它不是被
修好的,是随着伪装一起消失的。

## 5.5 rig:模型知道自己的关节是什么

**这一条是整份文档里唯一一条不讲"画法"的,但它比画法更重要。**

在它存在之前,人偶**不知道自己的任何一个关节是什么**。一个姿势是一张绝对角度表,
一次拖拽是自由的三维旋转——所以没有任何地方能告诉肘关节"你是一个铰链"。结果是
**我写的预设和用户的拖拽都能做出人体做不出来的身体**,而那,不是渲染,才是一部分
姿势怎么调都读着别扭的原因。

量出来的:全库里弯曲超过 20° 的膝盖,折向大约 7:1 分裂(有一条腿是反的);肘 3:1;
`crossLegged` 的膝盖整整偏离矢状面 **90°**——那是一个侧向折叠的膝盖。

### rig 是"约束"不是"存储"

`constrainFigure` 拿任意一组关节,返回**最近的合法姿势**。这样存档格式仍然是一串
朴素的点(所以以前存的每一张草图都还能打开),但**权威从数据移到了模型**。姿势能
进入系统的每一条路都走它:

| 入口 | 为什么必须走 |
|---|---|
| `createFigure`(预设) | 手写四十五个角度,总会写错几个 |
| `swingJoint`(拖拽) | 让不合法的姿势**拖不出来**,而不只是"没写进去" |
| `moveJoint`(Alt) | Alt 逃的是骨长,不是解剖 |
| `completeFigure`(重开草图) | 旧存档可能带着 rig 之前的姿势 |
| `figureFromLandmarks`(照片) | 估计器会给出反折的肢体 |

### 三类关节

- **铰链**(肘、膝):只在一个平面内、只往一侧弯。弯曲量上限(肘 148°、膝 150°),
  弯曲**法线的符号**决定往哪一侧——这就是肘和膝的全部区别。
- **父骨的扭转上限**:铰链摆动的那个平面会跟着父骨自转一起转。手臂给 85°(肱骨
  确实能转那么多),腿只给 45°——**股骨转 90° 正是盘腿时膝盖侧折的成因**。
- **锥形限位**(髋、头、脸):大腿离"正下方"最多 135°、过中线最多 30°;头离脊柱轴
  最多 62°;脸离身体正前方最多 85°(回头够得到,回头看背后够不到)。

### 两条踩过的坑

1. **符号不要手推。**canvas 的 y 轴朝下,这会悄悄翻转每一个叉积的手性。我手推的
   膝盖符号第一次就是反的。**两个符号都取自肉眼确认没问题的姿势**:膝看 `sitting`,
   肘看 `handsOnHips`。以后再有疑问,对这两个,不要对着解剖图。
2. **死区的方向。**`HINGE_DEADBAND` 是一个**余弦**,所以"大"意味着"直"。我第一版
   写成 `cos(83°)`,语义变成"弯曲不到 83° 就跳过"——**整个 rig 对几乎所有姿势都
   没生效,但看起来在跑**。测试里现在有一条专门守着这个:直的肢体不许被动,而全库
   的折向必须全部同号。

结果:膝盖 **0 处反向**(之前每侧 1 处),肘 **0 处反向**(之前 3 和 5 处),而 36 个
预设肉眼看没有一个被约束改坏。

## 5.6 两种体型,一套姿态库

人偶分 **女 / 男** 两种体型(`FigureBuild`,存在每个人偶上,`PoseFigure.build`)。
关键约束:**姿态库只有一份**。姿势是骨骼**角度**(`poses/spec.ts`),所以同一个
"跪坐"在两副骨架上各 build 一次就是同一个姿势——没有人需要维护第二张表。

### 不同的骨架,同样的大小

两种体型的骨长都从各自的白模上量(见 §2),所以不只是肩髋不同,四肢比例也不同。
共享的只有**躯干长度 0.36**:`figureUnit` 量的是躯干,所以**换体型不改变人偶大小**,
预设也都除以同一个 `POSE_SCALE`。

### 换体型 = 一次重定向

`setFigureBuild` 和照片导入用的是同一条规矩:**方向保留,骨长换成新骨架的**,髋根原地不动,
最后过 rig。所以姿势、大小、位置、视角都不变,只有肩宽和髋宽变。往返一次回到原样。

### 默认值

- 新人偶:跟随当前选中(或最后一个)人偶的体型;画布上一个都没有时用 `DEFAULT_BUILD`(女)。
  切换就在工具栏上,一次点击,不在落人偶之前问(原则 6)。
- 旧草图(没有 `build` 字段):读作 `LEGACY_BUILD`(男)。关节按存档原样保留,
  皮肤沿骨头拉伸去贴它们。
- 姿势库缩略图用当前人偶的体型画:一份库,但每格显示的是"套到这个人身上会是什么样"。

## 5.7 `bend` 的符号曾经是反的

`PoseSpec.bend` / `headNod` 的注释一直写着"+ 往身体前方折",代码里却取了负号——于是
**鞠躬、蹲、跑步的前倾全都是同等幅度的后仰**。正面看两者一模一样,侧面看正好相反,所以
36 个预设一直没人发现。现在符号跟着深度走,`build.test.ts` 有一条"鞠躬是向前的"守着它。

同一轮里还加了 `PoseSpec.body`(`spin` / `tip` / `turn`):`lean` 是在屏幕平面里转,
人倒下后胸口仍朝镜头——对"侧卧"是对的,对"趴着"、"四肢着地"、"俯卧撑"、"仰卧"是错的。
这些姿势现在按"站着、地板在身体前方"来写,然后整体放倒,再在地面上转 28°,避免正侧面时
左侧关节全被右侧挡住。

新增的地面姿势(`floor` 组:跪坐、跪坐后仰、侧坐、侧坐抱头、屈膝坐、四肢着地)和两个
躺卧姿势(侧卧撑肘、趴着托腮)取自经典人体速写参考。

## 6. 画法:透视化(半透明)、棚灯、墨线

人偶是**透明的**,像画在描图纸上:每个体块中间薄、边缘实(菲涅耳衰减),所以仍读得出
有光照的圆的体积,同时躯干后面的手臂、远侧的腿、背后的手都透得出来;体块交叠处层层
叠暗,正好说明"谁在谁前面"。人偶后面的笔迹也透得出来。

实现是几个按顺序的 pass:最近表面的深度(只写深度)→ 不做深度测试的半透明身体(每一层都
画)→ 结构线被挡住的那一半(淡)→ 轮廓墨线和结构线可见的那一半(实,对深度测试)。
所以一圈关节环是完整的一圈:前半实、后半虚,和结构素描一样。

(中间试过"左右冷暖 + 远处褪色"的配色,被否掉了:要的是透视化,不是颜色。)

主光左上前方、背后一盏轮廓光、天光冷/地光暖的半球补光。材质哑光,中性灰,不用肤色也
不用木色。三档明度给多人偶用,选中的人偶另戴一层冷色。

外加一圈**墨线**(反向外壳:表面沿法线外推、只画背面、深度往后偏移),给轮廓和形体之间
的遮挡一条线——图像模型最先读的就是线。深度偏移是为了不让外壳从锁骨这类浅凹处穿出来。

## 7. 改这份标准的规矩

1. 先改这份文档,说清楚**依据是什么**(某条画法的规矩、某个可测量的比例),
   再改代码。"我觉得好看"不是依据。
2. 改完**放大了看**。难看的东西只在放大后才明显,缩略图会替你遮丑——髋球画两遍
   那个 bug 藏了整整一版。
3. 全库所有预设 + 6 个视角一起看(`poseFigure.test.ts` 之外还有对照表):
   一个姿势好看不算数,**一张对照表上一眼看出来的问题才是真问题**。
4. **别在 2D 里画 3D。**这份文档前三版的绝大部分篇幅都在解决一个不该存在的问题。
   数据是三维的,画它的东西也必须是。任何"手工算遮挡 / 缩短 / 自交"的冲动都是信号。
5. **先找现成的,再考虑自己做。**白模这件事前五轮都在自己雕,第六轮换成 MakeHuman
   的基础网格才过关。
6. **先做样稿再动仓库。**真 3D 这一版是先在沙盒里用现有关节数据拼出来给人看、改了
   两轮形体、点头之后才搬进来的。看图比看参数快十倍。
