# 人偶标准(Mannequin Standard)

> 配套阅读:`sketch-canvas.md` §4(人偶在产品里是什么)、`pose-from-image.md`
> (从照片导入)。这份文档只回答一件事:**人偶应该长成什么样,以及为什么**。
> 它是画法的**基准**——任何一次改人偶的形,先改这里,再改 `poseFigure.ts`。
>
> 唯一的事实源是 `frontend/src/utils/poseFigure.ts` 里的 `BONE`(骨长)和 `MANIKIN`
> (每个实体的尺寸和两块躯干的旋转截面)。下面的数值是它们的说明,不是副本——
> 数字对不上时,以代码为准,并回来修这份文档。

---

## 0. 这份标准是怎么来的

前后返工了四轮,每一轮都是"我觉得这样好看"。第四轮的反馈是一句很准的话:
**"应该多看看行业里面大家是怎么做的,特别是美术相关的"**。去看之后,有两条
我自己拍脑袋定下的结论被直接推翻:

1. **关节应该收窄,不是鼓起来。**我一直在把球画得更好看,方向从一开始就错了。
2. **头不是太大,是太小。**上一轮我把头缩了一档,人直接变成 8.7 头身——那是
   时装插画的比例,不是人。

教训写在这里,而不是留在对话里:**对着参考图调参数是没有收敛点的,对着画法
的规矩调才有。**

## 1. 比例:Loomis 八头身

以头长为 1,从头顶往下数:

| 位置 | 头数 |
|------|------|
| 下巴 | 1 |
| 乳线 | 2 |
| 脐 | 3 |
| 耻骨(**正中**) | 4 |
| 膝 | 6 |
| 脚底 | 8 |

肩宽约 **2 个头**,胯宽约肩宽的 **3/4**(约 1.5 个头)。这套是画人体的通用基准,
不是风格选择:偏离它的人偶,第一眼就会被读成"比例不对",而看的人往往说不清
哪里不对。

实现上比例落在 `BONE`(骨长,任意单位、最后归一化)。检验方式是量出来的
头身比,而不是看着像不像——**人偶的比例是一个可测量的量**。

## 2. 形体:它是一堆实体,不是一堆轮廓

**这一条改过四次。前三次都是在 2D 画布里画一个 3D 的东西,第四次不画了。**

1. 三个凸体块各自打光 → "三个蛋摞着"。
2. 一条闭合轮廓 + 腰上一道线 → 形是整的,腰读不出来。
3. 两块轮廓 + 腰球,手工偏移轮廓、手工深度排序、手工缩短、手工处理肢体折回去的自交
   → 每一处"看着怪"都是这层伪装漏出来的,而每一轮都在给伪装打补丁。
4. **真 3D**(现在):人偶就是十几个球、锥柱和两个旋转体,用 WebGL 在真实光线下渲染
   (`poseFigure3d.ts`)。遮挡、缩短、光影不再是算出来的近似,是**免费且正确的**。

关键的一句:**数据早就是三维的**(骨架、rig、相机、预设、手柄、照片回算全在 3D 里),
只有"画出来"这一步在假装。所以换掉的只有"关节 → 图像"这一段,其余一行没动。

现在的形体(`MANIKIN`,全部是身高的分数):

| 部件 | 形 | 尺寸 |
|---|---|---|
| 头 | 近球的椭球 | 0.058 / 0.066 / 0.060 |
| 脖子 | 圆柱 | r 0.027 |
| 胸 | **旋转体**,底在腰、顶在颈,最宽处在肩线、其上迅速收口(肩是胸块的**顶**,不是颈下的台阶) | 最宽 0.092,厚度 ×0.56 |
| 腰球 | 球,露在胸和盆之间的真空隙里 | r 0.030 |
| 盆 | **旋转体**桶形,髂嵴最宽、收到髋关节 | 最宽 0.080,厚度 ×0.60 |
| 肩球 / 髋球 | 球 | 0.027 / 0.028 |
| 上臂 → 肘 → 腕 | 锥柱 + 肘腕小球 | 0.030 → 0.026 → 0.019 |
| 手 | **一颗小球**,不是刀片(刀片读成尖刺) | r 0.025 |
| 大腿 → 膝 → 腓肠 → 踝 | 锥柱,小腿在膝下三分之一最粗 | 0.041 → 0.029 → 0.033 → 0.022 |
| 脚 | 圆垫,朝身体正前方 | 0.062 × 0.024 |

这张表**只有一份**:渲染器把它变成网格,命中测试把它投影成 2D 胶囊,边界框按它加边。
一份几何,不许有第二张表——那是"能抓的"和"能看的"漂移开的唯一途径。

整体偏瘦是刻意的:第一版 3D 躯干宽到读成盔甲。木偶是个轻巧的东西。

### 相机必须和 `projectionOf` 逐像素一致

蓝色手柄是从 `projectFigure` 画的,身体是 WebGL 画的,两者对不上就是灾难。所以 3D
相机就是 `projectionOf` 描述的那台针孔相机:针孔在人偶自己的锚点、焦距一个
`distance`、画布是这台相机视野里的一扇**偏心的窗**(`setViewOffset`)。近裁剪面放在
`perspectiveAt` 开始钳制的地方,拖进镜头的关节会被裁掉而不是炸满画布。

### 一个共享的 WebGL 上下文

所有绘制都进同一个离屏 WebGL 画布,再 `drawImage` 到调用方的 2D 画布上。草图表面
仍然是普通 canvas(笔迹、导出、mock 后端都不知道 WebGL 存在),而姿势库一格一格
三十六个缩略图共用一个上下文——浏览器对活着的 WebGL 上下文有十来个的上限。没有
WebGL 的地方退回平涂的投影胶囊:难看,但诚实。

## 3. 关节:球窝有球,铰链收窄

**这是整份标准里最重要的一条,而且它返工过两次,两次方向相反。**

第一版:每个关节一个球(肩、肘、腕、髋、膝、踝),照着实体木头人偶抄。读起来像玩具。

第二版:**全部去掉**,理由是"实体人偶在关节处鼓起是为了能转,那是制造工艺不是形体;
画画的人在关节处是收窄的"。这条理由本身没错,但**推得太远了**。

现在:**看真的木头人偶,它自己就给出了分界线**——

| 关节 | 人偶上是什么 | 我们怎么画 |
|------|--------------|------------|
| 肩、髋 | 明显的**球**(球窝关节,球就是关节本身) | 一颗真的球,在 3D 里自然地被躯干和肢体部分遮住 |
| 肘、膝、腕、踝 | **收窄**,一根销钉——上臂往下收到肘,小臂从肘再往下收到腕 | 锥柱向关节收窄,关节处一颗和肢体同径的小球 |

所以"关节处收窄"这条规矩是对**铰链**说的,不是对**球窝**说的。把球抄到铰链上,人偶
读成玩具;把球从球窝上也拿掉,肩膀就没有了转轴,手臂像是从躯干侧面长出来的。

半径表(占身高比例,`R`):

| 节点 | 半径 | 规矩 |
|------|------|------|
| 上臂 | 0.031 | 上臂**几乎不收**,从上到下差不多粗 |
| 肘 | 0.028 | 比上臂略窄 |
| 腕 | 0.019 | |
| 大腿 | 0.043 | |
| 膝 | 0.030 | **掐进去** |
| 腓肠 | 0.034 | 小腿**最粗处在膝下三分之一**,不是从膝往下直接收 |
| 踝 | 0.023 | |
| 髋球 | 0.031 | 球窝,属于骨盆 |
| 肩球 | 0.034 | 球窝,属于躯干 |

关节处的小球和肢体同一种材质、同一个半径:你看见它靠的是光在球面上的转折,不是颜色。

手和脚是肢体的**末端**(接在腕/踝之后的两个节点),不是贴上去的锭子。手比腕
只宽一点点就够读成手;明显更宽就成了烤箱手套。

## 4. 脖子向前 7°

`NECK_FORWARD = 7`。垂直的脖子是一根桅杆,人的颈椎从来不垂直。这一条便宜到
几乎不要钱,但它是"这个人偶像个人"和"像个衣架"的差别之一。

## 5. (已删)折回去的肢体拆成两片

2D 时代肢体折回自己身上会让单条轮廓自交、填出一片鳍,所以要在折点拆成两片按深度排。
真 3D 里两根锥柱本来就是两个物体,这个问题**不存在**。保留标题是为了说明:它不是被
修好的,是随着伪装一起消失的。

## 5.5 rig:模型知道自己的关节是什么

**这一条是整份文档里唯一一条不讲"画法"的,但它比画法更重要。**

在它存在之前,人偶**不知道自己的任何一个关节是什么**。一个姿势是一张绝对角度表,
一次拖拽是自由的三维旋转——所以没有任何地方能告诉肘关节"你是一个铰链"。结果是
**我写的预设和用户的拖拽都能做出人体做不出来的身体**,而那,不是渲染,才是一部分
姿势怎么调都读着别扭的原因。

量出来的:全库里弯曲超过 20° 的膝盖,折向大约 7:1 分裂(有一条腿是反的);肘 3:1;
`crossLegged` 的膝盖整整偏离矢状面 **90°**——那是一个侧向折叠的膝盖。

### rig 是"约束"不是"存储"

`constrainFigure` 拿任意一组关节,返回**最近的合法姿势**。这样存档格式仍然是一串
朴素的点(所以以前存的每一张草图都还能打开),但**权威从数据移到了模型**。姿势能
进入系统的每一条路都走它:

| 入口 | 为什么必须走 |
|---|---|
| `createFigure`(预设) | 手写四十五个角度,总会写错几个 |
| `swingJoint`(拖拽) | 让不合法的姿势**拖不出来**,而不只是"没写进去" |
| `moveJoint`(Alt) | Alt 逃的是骨长,不是解剖 |
| `completeFigure`(重开草图) | 旧存档可能带着 rig 之前的姿势 |
| `figureFromLandmarks`(照片) | 估计器会给出反折的肢体 |

### 三类关节

- **铰链**(肘、膝):只在一个平面内、只往一侧弯。弯曲量上限(肘 148°、膝 150°),
  弯曲**法线的符号**决定往哪一侧——这就是肘和膝的全部区别。
- **父骨的扭转上限**:铰链摆动的那个平面会跟着父骨自转一起转。手臂给 85°(肱骨
  确实能转那么多),腿只给 45°——**股骨转 90° 正是盘腿时膝盖侧折的成因**。
- **锥形限位**(髋、头、脸):大腿离"正下方"最多 135°、过中线最多 30°;头离脊柱轴
  最多 62°;脸离身体正前方最多 85°(回头够得到,回头看背后够不到)。

### 两条踩过的坑

1. **符号不要手推。**canvas 的 y 轴朝下,这会悄悄翻转每一个叉积的手性。我手推的
   膝盖符号第一次就是反的。**两个符号都取自肉眼确认没问题的姿势**:膝看 `sitting`,
   肘看 `handsOnHips`。以后再有疑问,对这两个,不要对着解剖图。
2. **死区的方向。**`HINGE_DEADBAND` 是一个**余弦**,所以"大"意味着"直"。我第一版
   写成 `cos(83°)`,语义变成"弯曲不到 83° 就跳过"——**整个 rig 对几乎所有姿势都
   没生效,但看起来在跑**。测试里现在有一条专门守着这个:直的肢体不许被动,而全库
   的折向必须全部同号。

结果:膝盖 **0 处反向**(之前每侧 1 处),肘 **0 处反向**(之前 3 和 5 处),而 36 个
预设肉眼看没有一个被约束改坏。

## 6. 画法:一盏棚灯,中性灰

一盏固定的主光(左上前)、一盏右侧补光、一层环境光——每张美术参考照片都是这么打的。
材质 `roughness 0.62`、无金属度:哑光,像打磨过的木头,但**不用木色**。木色只会邀请
模型画一个木头娃娃;人偶的结构才是信息。三档明度(躯干色 `#c3c7cc` / `#a4aab1` /
`#d8dce1`)是给多人偶用的——两个同色的人偶叠在一起会糊成一团,模型就数不清画面里
有几个人;选中的人偶另戴一层冷色。

之前那套"线为主、明暗为辅"的画法连同轮廓线一起删了:它是给一个没有真实明暗的
2D 形体补形用的。现在明暗就是真的。

## 7. 改这份标准的规矩

1. 先改这份文档,说清楚**依据是什么**(某条画法的规矩、某个可测量的比例),
   再改代码。"我觉得好看"不是依据。
2. 改完**放大了看**。难看的东西只在放大后才明显,缩略图会替你遮丑——髋球画两遍
   那个 bug 藏了整整一版。
3. 全库 36 个预设 + 6 个视角一起看(`poseFigure.test.ts` 之外还有对照表):
   一个姿势好看不算数,**一张对照表上一眼看出来的问题才是真问题**。
4. **别在 2D 里画 3D。**这份文档前三版的绝大部分篇幅都在解决一个不该存在的问题。
   数据是三维的,画它的东西也必须是。任何"手工算遮挡 / 缩短 / 自交"的冲动都是信号。
5. **先做样稿再动仓库。**真 3D 这一版是先在沙盒里用现有关节数据拼出来给人看、改了
   两轮形体、点头之后才搬进来的。看图比看参数快十倍。
